Ten presentational attributes on `table` are obsolete. `<table width="100%" border="1" cellpadding="4" cellspacing="0" bgcolor="#ffffff">` is how tables
were styled before CSS. They set the table's size, borders, spacing and alignment; `bgcolor` set
the colour and `bordercolor` coloured the frame. They still turn up in old pages and in HTML
generated by older tools.

## Why avoid

They are obsolete. The HTML Standard lists `align`, `bgcolor`, `border`, `bordercolor`,
`cellpadding`, `cellspacing`, `frame`, `height`, `rules` and `width` on `table` among the
attributes that "are obsolete (though the elements are still part of the language), and must not
be used by authors", with the instruction: "Use CSS instead." None of them survives in a
conforming form. The standard's short list of obsolete but conforming features keeps a `border`
attribute only on `img`, and only as `border="0"`.

The styling attributes still work, which is what makes them a problem. The rendering section turns
each into a presentational hint. "The table element's cellpadding attribute maps to the pixel
length properties 'padding-top', 'padding-right', 'padding-bottom', and 'padding-left'" of its
cells, `cellspacing` maps to `border-spacing`, `width` to `width`, `border` to the table's border
widths, and `align="center"` becomes `margin-inline: auto`. Those hints sit in the weakest place in
the author's part of the cascade. HTML calls them "the author-level zero-specificity presentational
hints part of the CSS cascade", and CSS Cascade 5 gives them their own origin, "between the regular
user origin and the author origin".

So any stylesheet rule for the same property wins. Each attribute either does nothing,
because CSS overrides it, or sets a value the stylesheet never mentions. Either way, part
of the table's design lives in markup, where nobody editing the CSS will look for it.

MDN files the sibling hints under deprecated
attributes with CSS beside each, and notes that no HTML specification includes `height` as a
`table` attribute while some browsers honour a non-standard reading of it as a minimum height: use
`min-height` instead.

`summary` on `table` is obsolete too, but it describes the table rather than styling it, and its
replacement is a `<caption>`, not CSS. `attr/table-summary` covers it.

## Use instead

Move the styling to CSS:

```html
<table class="prices">
  <caption>Plans and monthly prices</caption>
  <thead>
    <tr><th scope="col">Plan</th><th scope="col">Price</th></tr>
  </thead>
  <tbody>
    <tr><td>Basic</td><td>CHF 9</td></tr>
  </tbody>
</table>
```

```css
.prices {
  width: 100%;
  min-height: 10rem;
  margin-inline: auto;
  border-collapse: collapse;
  border-color: #ccc;
  background-color: #fff;
}
.prices th,
.prices td {
  padding: 0.25rem 0.5rem;
  border: 1px solid #ccc;
}
```

| Attribute | CSS instead |
|---|---|
| `width` | `width` |
| `height` | `min-height` |
| `align="center"` | `margin-inline: auto` |
| `bgcolor` | `background-color` |
| `border`, `frame`, `rules` | `border` on the table and its cells, `border-collapse` |
| `bordercolor` | `border-color` |
| `cellspacing` | `border-spacing` |
| `cellpadding` | `padding` on `th` and `td` |

## Detectability

Complete detection. The rule reports each table once, however many of the ten attributes it
carries. It checks only the `table` element, and skips the same obsolete attributes on rows and
cells. There is no autofix: removing a live hint repaints the table wherever no stylesheet rule
covers the property, so the move to CSS needs a human look at the values.

## Resources

- [HTML Standard: Non-conforming features](https://html.spec.whatwg.org/multipage/obsolete.html#non-conforming-features): all ten attributes on `table`, `bordercolor` and `height` included, are obsolete; use CSS instead.
- [HTML Standard: Obsolete but conforming features](https://html.spec.whatwg.org/multipage/obsolete.html#obsolete-but-conforming-features): the only conforming `border` attribute left is `border="0"` on `img`.
- [HTML Standard: Rendering: tables](https://html.spec.whatwg.org/multipage/rendering.html#tables-2): how each attribute maps to `padding`, `border-spacing`, `width`, border widths and `margin-inline`.
- [HTML Standard: The CSS user agent style sheet and presentational hints](https://html.spec.whatwg.org/multipage/rendering.html#presentational-hints): presentational hints are author-level with zero specificity.
- [CSS Cascading and Inheritance Level 5: Precedence of non-CSS presentational hints](https://www.w3.org/TR/css-cascade-5/#preshint): hints form their own origin, below author styles.
- [MDN: `<table>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/table): the sibling hints sit under deprecated attributes with CSS beside each, and `height` carries a note that no HTML specification includes it, with `min-height` as the replacement.
