Four presentational attributes on `input` are obsolete. `<input type="image" src="go.png" alt="Go" align="middle" border="1">` is how image buttons were dressed before CSS. The attributes settled image buttons and spaced controls. They still turn up in old pages and in HTML generated by older tools.

## Why avoid

They are obsolete. The HTML Standard lists each spelling among the attributes that "are obsolete (though the elements are still part of the language), and must not be used by authors", with the instruction: "Use CSS instead." Section 16.3 still backs `align` with a reflected IDL member, which is live machinery: the attributes keep working as presentational hints in the weakest place in the author cascade, where any stylesheet rule for the same property wins.

So deleting one repaints the control wherever no stylesheet rule covers the property. Each attribute either does nothing, because CSS overrides it, or sets a value the stylesheet never states. Either way, part of the page design lives in markup, where nobody editing the CSS will look for it. MDN tabulates the full live `input` attribute set with none of the four among them.

## Use instead

Move the control chrome to CSS and drop the hints:

```html
<input type="image" src="go.png" alt="Go">
```

```css
input[type="image"] {
  vertical-align: middle;
  border: 1px solid #ccc;
  margin: 0 0.5rem;
}
```

## Detectability

Complete detection. The rule reports each `input` once, however many hints it carries. It checks the `input` element and nothing else. There is no autofix: removing a live hint repaints the control, so the move to CSS needs a human look at the values.
